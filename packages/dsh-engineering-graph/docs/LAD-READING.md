# 读一段 LAD 的固定顺序

> 适用：`@automation-suite/engineering-graph` 的 `knowledge_*` 工具。
> 这份文档解释**怎么读**。工具保证的是"事实"（结构、读写、扫描序），不是结论。

## 1. 符号表（`view='ladder'` 的文本约定）

阶梯文本一行 = 一条**从电源轨到终点的通路**。行格式：

```
  <线圈标记> <被写目标>   <-  <这一行的条件>
  -- (no coil)   <-  <不通向线圈的通路条件>
```

| 写法 | 含义 |
|---|---|
| `(=) X` | 赋值线圈：X := 条件 |
| `(S) X` / `(R) X` | 置位/复位线圈：条件为真时置位/复位一次（**保持型**，不等于赋值） |
| `(/)(=) X` | 取反线圈：X := NOT(条件) |
| `-- (no coil)` | 该通路通向**开口端**而不是线圈（EN 链、报警接线）。**它不写线圈，但行内的盒子在 RLO 为真时照样执行**——所以 `[Move …]` 仍然会写 |
| 同一线圈**多行** | 这些条件互为**或**（并联分支） |
| 行内 `AND` | 串联条件 |
| `NOT x` | 常闭触点 |
| `[<指令> <操作数…>]` | 盒指令/调用，操作数**按引脚顺序**（`in1`, `in2`, …）从左到右 |
| `[Eq a, 7]` | 比较：等价于 `a = 7`（`in1` 在左）。`Ne`、`Gt`、`Ge`、`Lt`、`Le` 同理 |
| `[Move src -> dst]` | 数据方向：`src` 写入 `dst`（`->` 右边是被写目标） |
| `[TON T[0] T#500ms]` | 计时器，实例 `T[0]`，后面是其余输入（此处为 `PT`） |
| `[InRange min, x, max]` | 区间比较，三个操作数依次是**下限、被比较值、上限**（等价 `min <= x <= max`） |
| `[058_PosSpdControl Inst, a, b]` | 块调用：`Inst` 是实例，其后是按引脚顺序的实参 |
| `PContact(operand, mem=bit)` | 正边沿触点：`operand` 是被检信号，`mem=` 是边沿记忆位 |
| `PBox(mem=bit)` / `NContact` / `NBox` | 其余边沿指令；**指令名保持全称**，不要简记为 `P` |
| `X[9].Y` | 数组元素成员；`[9]` 是下标，属于名字的一部分 |

**盒指令的边界（最容易被误读的地方）**：方括号里给出的是它的**操作数与数据流向**，不是它**算出的结果**。
- 计时器：方括号说"哪个实例、预置值多少"，但 `Q`/`ET` 是这条指令**自己产生**的，不写在行里——要判断
  "Q 何时为真"，看它是否被别处读到，以及 `Q` 接到了什么（本行后续条件已经体现了这一点）。
- 块调用：结果由**那个块自己的网络**决定，必须再读那个块。
- 别把 `-- (no coil)` 行里的 `[Move …]` 当成"不执行"：它不写线圈，但盒子照样执行。

## 2. 五个角度，各回答什么

| 角度 | 工具 | 能确定的事实 | 不能确定的 |
|---|---|---|---|
| 结构 | `knowledge_network(view='ladder')` | 哪个线圈、由哪些条件（与/或）达成；盒子的操作数与数据方向 | 盒指令内部算出的条件 |
| 数据流 | `knowledge_network` 的 `Writes/Reads` | 这个网络读写了哪些变量（含数组元素下标） | 谁在别处也写它 |
| 扫描时序 | `knowledge_variable_usage` 的 `Scan order` | 读到的是同拍还是上一拍；多个写入谁赢 | 跨块顺序（依赖调用链） |
| 业务意图 | 网络标题、变量名、注释 | 这段在工艺上做什么 | 是否符合安全规范 |
| 验证 | 仿真/在线监控 | 运行时的真实值 | — |

## 3. 读取顺序

1. `knowledge_block` 列出网络与索引，先看**写集合**定位到相关网络，不要从头读。
2. 对候选网络用 `view='ladder'` 读结构（按第 1 节的符号表）：
   - 同一线圈多行 = 这些条件互为或；
   - `NOT x` = 常闭；`(S)`/`(R)` = 保持型置位/复位；
   - `-- (no coil)` = 该路径不通向线圈。
3. 碰到方括号里的盒指令，判断"它内部是什么条件"时**再读它自己的网络**（块调用）或该块的实现，
   不要把它当成一个普通触点。
4. 涉及"这个值什么时候是新的"时，用 `knowledge_variable_usage`：
   - `read at N runs after write at M — same scan`：读到的是本拍新值；
   - `read at N runs before write at M — it sees the PREVIOUS scan's value`：**读的是上一拍**；
   - `written at ... — the later network wins`：多处写，扫描序靠后者生效；
   - `never written in this database`：值来自 HMI/硬件/不在库里的块。
5. 需要跨块时，先确认调用关系（`knowledge_query` 查 `CALLS` 边），再判断谁先执行。

## 4. 三条红线

1. **`Ladder view: not available`** 时不要猜结构：那可能是 SCL 区域或旧库（旧库需要重新 ingest 才有该视图）；改用语句文本读。
2. **方括号只给操作数与流向**，不给盒内的计算结果。不要把 `[Eq a, 7]` 当成"某个触点的名字"，也不要把 `[Move src -> dst]` 的方向读反（`->` 右边才是被写目标）。
3. **阶梯视图给的是"条件"，不是"值"**。取反线圈已标注 `(/)(=)`；置位/复位是保持型，不能按"等于条件"理解。

## 5. 常见误判

| 误判 | 事实 |
|---|---|
| 把并行分支读成串联 | 同一线圈多行才是并联 |
| 把 `(S)`/`(R)` 当赋值 | 它们是保持型，条件为真时置位/复位一次 |
| 把 `[Move a -> b]` 读成 `a := b` | `->` 右边是被写目标：`b := a` |
| 把 `[Eq a, 7]` 读成 `7 = a` 之外的顺序猜测 | 操作数按引脚顺序，`in1` 在左 |
| 把两个同名盒当成同一个 | 例：两个 `[Move …]` 靠操作数区分，现在能看出各自的源与目标 |
| 忽略一拍延迟 | 生产者网络号大于消费者网络号时，读到的是上一拍 |
| 把实例 DB 成员当变量 | `G_PLS_Transfer_Cav_A.Mvt_VocDoor_Ask` 是块接口，写入方是那个块 |
| 认为一处写入就是唯一写入 | 用 `knowledge_variable_usage` 查全部写入者 |
| 把数组元素合并 | `IO_MotionPara[9]` 与 `IO_MotionPara[2]` 是不同节点；下标属于名字 |

## 6. 这些结论来自哪里

- 结构规则由 TIA V17 实测确定（`docs/research/tia-lad-structure-rules.md`）：线圈可在分支中间、嵌套分支、扇出、取反触点、同位 S/R 双写均合法。
- 阶梯视图与语句翻译的一致性由等价校验保证；另有四条不变量（线圈成行、操作数不丢、实例下标保留、同名盒可区分）在参考工程 4058 个网络上全量校验。
- 扫描序是 IEC 61131-3 语义：块内网络自上而下执行一次，后写者胜。
