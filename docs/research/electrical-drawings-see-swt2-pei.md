# SWT2_PEI_1026_Night 电气图纸（SEE Electrical 打印件）结构与信息提取研究

- 研究对象：`E:\PEI---SWT2_20260527.pdf`（4.86 MB，353 页，2026-05-27 13:40 打印）
- 研究目的：判断"把图纸里的有效工程信息抽出来"要做到哪一步、怎么做，为后续插件（图纸查阅能力）定数据模型与边界
- 方法：先读卷首目录判断架构，再按 10 类页面模板抽样读内容与几何，最后用脚本对全 353 页做可行性实测（脚本与中间产物见附录 B）

## 0 结论摘要

1. **不是扫描件**。353 页全部有可用文本层（子集 Type1 字体，有一处字形映射缺陷），不需要 OCR。成本不在"识别"，而在"把散落的文本按 SEE 的制图约定重新结构化"。
2. **一份 PDF = 三个电柜的打印作业**，拼接而成：`AG`（81 页）、`COF-BASE-A`（135 页）、`COF-BASE-B`（137 页）。三个柜各用一套独立图号，**图号在整份 PDF 内不唯一**——主键必须是 `(电柜, 图号)`。后两个柜是孪生结构（BASE-A/LID-A 与 BASE-B/LID-B），模板与图号编排几乎一一对应。
3. **全篇只有 10 类页面模板**，8 类有内容。其中电缆详图、端子、连接器针脚、目录这四类是"表格型"，字段是按固定标签绘制出来的（`Type:`/`Strands:`/`Section:`…），可以用"标签→值 + 列带宽"直接抽；原理图页靠 SEE 自己写在图上的位号、线号、PLC 地址、交叉引用就能支撑"查阅"，**不需要重建网表**。
4. **卷首目录（SUMMARY）与纸面不一致**：它列了 `8004-8014 端子块`、`8500-8509 电缆`、`9000-9002 电缆清单`、`9500-9505 部件清单`，而实际打印出来的是 `4000-4009`、`3000-3023`，电缆清单与部件清单**根本不在打印件里**。索引只能从每页图框现场生成。
5. 实测可行性（全量 353 页）：
   - 图号/标题/位置索引：**350/353 页**取到图号（3 页 MAIN PAGE 本身无图号）
   - 交叉引用：**1,669 条**，**100%** 能解析到纸面上真实存在的图号，91.5% 落在本柜内
   - 电缆表：电缆详图页上 **348/355 根（98%）** 抽出类型/芯数/截面/长度/两端/芯线表，共 **3,016 条芯线**
   - 全文检索 + 命中定位：**74,598 个词簇**（平均 211/页），词框落墨检验 **100%** 命中（24 页方向异常页除外）
   - 位号/线号/PLC 地址索引：**252 个位号**（放宽到 `MOD`/`REP` 类标注则 350 个）/ **294 个线号** / **341 个 PLC 地址**
6. **不建议做**：电气网表（连通性）重建。这套图的符号是拆散的线段（内容流里只有 `m`/`l`/`S`，没有可复用的 symbol XObject），要恢复连接关系得做几何推理，投入与收益不成比例；而"查阅"这个目标并不需要它。

## 2 三级结构

### 2.1 文档级：三个打印作业 = 三个电柜

| Block | PDF 页 | 电柜（localisation） | 图纸数 | 卷首 |
|---|---|---|---|---|
| 1 | 1–81 | `AG`（主柜） | 80 | 1 MAIN PAGE + 2 REVISIONS + 3–5 SUMMARY |
| 2 | 82–216 | `COF-BASE-A` + `COF-LID-A`（A 腔底座与盖板） | 134 | 82 MAIN PAGE + 83 REVISIONS + 84–88 SUMMARY |
| 3 | 217–353 | `COF-BASE-B` + `COF-LID-B`（B 腔底座与盖板） | 136 | 217 MAIN PAGE + 218 REVISIONS + 219–223 SUMMARY |

三个 block 的分界点是各自的 `MAIN PAGE`（封面，带工程名、选项清单、柜名）。判定方法可靠：`MAIN PAGE` 是唯一"标题块里 sheet 号为空"的页面类型。

**Block 2 与 Block 3 是孪生体**：图号编排族、页数、模板完全对应（见附录 A），差异只在细节（电缆号 W 段、通道数量、连接器页 20 vs 22 张）。这意味着：**通用解析器写一次，两个柜共享**。

### 2.2 图纸级：每页都是一个图框 + 一张图

图框字段（实测位置，显示坐标系 842×595，原点左上）：

| 字段 | 位置（约） | 字号 | 抽取方式 |
|---|---|---|---|
| 图号（SHEET） | x≈780, y≈540 | 12 | 找 `SHEET` 标签右侧的 12 号数字——**唯一可靠来源** |
| 图纸标题 | x≈500–700, y≈540 | 8 | 标题块内 8 号字，排除固定串 `MAIN CABINET` |
| 位置（LOCALISATION） | x≈40, y≈76 | 8 | `LOCALISATION :` 后取值 |
| 上一张 / 下一张 | x≈769（`◀`） / x≈797（`▶`）, y≈556 | 8 | **图框自带图序链**（见下） |
| 工程身份 | 分散在左下半 | 4–12 | 见 §1.2 |
| 列标 `1..39` | y≈23（下边）、y≈8（上边） | 7 | 交叉引用的"列号"就是这里的列标 |
| 行标 `A..J` | x≈8 / x≈834 | 7 | 同上 |

> **图框自带"上一张/下一张"**（如 sheet 500 的框上印着 `◀313`、`501▶`）是这份 PDF 里最被低估的结构：即使目录页作废，也能从每页图框重建整册的图序。
>
> 实测：**98 页**能稳定解析出这对字段（电缆页 55 + 原理图页 43），其中"上一张"**98/98** 与纸面图序完全一致；"下一张"92/98 一致，6 条偏差全是三位数被画得紧贴箭头、被切成 `21`/`31`/`41`/`121` 的分词假象（真值 `211`/`311`/`411`/`1211`）。其余页面这一对字段没有印刷，图序按页序本身推断即可（本 PDF 的页序 = 图序，已由 98 条校验佐证）。

## 4 目录页不可信：实测偏差清单

卷首 `SUMMARY`（Block 1 的 3–5 页）分辨率很高、读起来很正规，但**和纸面内容对不上**：

| SUMMARY 声明 | 纸面实际 | 判定 |
|---|---|---|
| `8004–8014 TERMINAL BLOCK : X2A …`（11 张） | `4000–4009 TERMINAL : X2A & X2B …`（10 张） | 同一批端子，**图号方案已改** |
| `8500–8509 CABLE : W025,W170,…`（10 张） | `3000–3023 Cable : W021,W025,…`（24 张） | 同一批电缆，图号方案已改且页数增加 |
| `9000–9002 CABLES LIST`（3 张） | **不存在** | 打印作业未包含 |
| `9500–9505 PART LIST`（6 张） | **不存在** | 打印作业未包含（全文档只在这 3 页目录里出现过 "PART LIST" 字样） |
| 未列出 | `111`、`113`、`156`、`272`、`275`、`276`、`277`、`3014–3023`、`4013`、`4016` 等 | 目录没写、纸上有 |

**结论（对插件是硬约束）**：

- 索引**不能**从 SUMMARY 页解析得出，必须逐页读图框；
- SUMMARY 只可作为"历史快照/差异对照"资产，用于发现"图纸被改过但目录没重生成"；
- 电缆清单、部件清单（BOM）在打印件里没有，只能从电缆详图页与原理图**重建**（§7.2 已实测可行）。

## 5 页面模板逐类解剖

### 5.1 卷首页（1 主图 / 2 修订 / 3–7 目录）

- **MAIN PAGE**：工程名、柜名、`OPTION LIST`、`DTM CLASS`、`5-5-3 REFERENCE` + 一张封面位图。抽：工程身份、柜名。
- **REVISIONS**：`REV / MODIFICATIONS / DATE / DRAWN / VERIFIED / APPROVED` 表，5 条历史（2017/7/18 建文档 → 2019/10/28 版次 D）。抽：版次历史。
- **SUMMARY**：每条 `图号 | 标题1 | 标题2 | 位置 | 版次 | 日期 | 绘制 | 校核 | 批准 | 修改`。**仅供参考**（§4）。

### 5.2 电源与配电页（100–182）

例：sheet 101 `POWER SUPPLY BOX` 画四路（Q1/Q2/Q3/Q4 塑壳，`63A`/`80A` 交替）+ 出线电缆 `W001/W002/W501/W502`（`4 x 16.00` / `4 x 25.00`，`OLFLEX 191` / `ÖLFLEX® CHAIN 896 P`）+ 交叉引用 `A(1100-8)`、`B(1100-8)`（去盖板 A/B 的母线）。

抽：断路器位号与整定值、电缆位号与芯数截面、去向交叉引用。

### 5.3 PLC 机架与通道页（200–299 / 1200–1299）★ 信息密度最高

例：sheet 210 `AG : 8 SAFETY LOGICAL INPUTS`（对应 PDF 第 25 页）：

```

巨框底部：            200MOD2   SIEMENS   6ES7136-6BA01-0CA0   F-DI 8X24VDC HF   STATION: AG  RACK: AG  MODULE: 1
每通道一列（80 pt 一列，8 列）：
                      %I400.0   ← PLC 地址
                      9A 1A 1 9 ← 模块端子/针脚
                      210.11 210.VS0 ← 线号
                      X3 7 / X3 1 ← 端子排与位置号
                      W015 0.00m 12x1.00 OLFLEX 150 QUATTRO ← 电缆
                      (220-14) ← 交叉引用（去 sheet 220 第 14 列）

这一页同时说清了：**哪个 PLC 通道 ↔ 哪根线 ↔ 哪个端子 ↔ 哪根电缆的哪根芯 ↔ 现场哪个元件**。一页 = 一张完整的"通道台账"，是插件最该做的结构化对象。

### 5.4 IO-Link / 无源模块页（300–415 / 1400–1406）

模块级：`RIO-COUPELLE_A` 之类的远程模块，端口 → 位号 → 交叉引用；无源模块（`R-HYD-PC-1`、`R-PP-1`、`R-TC-1-A`）是接线端子盒示意图。抽：端口表、模块型号、位号。

### 5.5 端子页（4000–4003 与目录里的 8004+）

例：sheet 4000 `TERMINAL : X2A & X2B`：

```
X2A            ← 端子排名（12 号字，独立标注）
 ┌ 110.04 | 1 | 110.05 ┐   ← 内侧位号 | 端子序号 | 外侧位号

## 6 图内语义元素：什么叫"有效工程信息"

这套图的文本层里混着 6 种不同性质的东西（图框固定字样、工程身份、器件参数、位号/线号、交叉引用、自由文本）。下面这张表就是**抽取规则的依据**，也是插件数据模型的字段来源：

| 元素 | 书写形式 | 实测数量 | 含义 | 用途 |
|---|---|---|---|---|
| **元件位号** | `220KA3`、`101Q1`、`200MOD2`、`210S1`、`100REP1` | 严格式 `图号+1–2字母+序号`：252 个 / 707 次；放宽到 `MOD`/`REP`/`L` 类标注：350 个 / 1,236 次 | 前 3 位 = **该元件所在图号**，其余是类型+序号 | 定位（"这个继电器在哪张图/哪个柜里"） |
| **线号** | `210.11`、`210.VS4`、`240.02` | 294 个 / 844 次 | 前 3 位 = 该线所在图号，`.` 后是线号 | 跨图追踪同一根线 |
| **PLC 地址** | `%I400.0`…`%I1500.7` | 341 个 / 341 次 | S7 绝对地址（I/Q + 字节.位） | 与 TIA 变量表对齐 |
| **电缆位号** | `W015`、`WT01`、`W6` | 420 个（其中 348 根有详图） | W = 电缆，WT = 特殊/屏蔽电缆 | 与电缆表、端子页对齐 |
| **端子排** | `X3`、`X3.FT`、`X10.FT`、`X2A` | 15 个排 | 端子排 + 派生排 | 接线查询 |
| **交叉引用** | `(220-14)`、`A(1100-8)`、裸写 `110-7` | 1,669 条（括号/侧别） | `(图号-列号)`，列号对应图框列标 1..39 | **跳转的核心** |
| **器件参数** | `6ES7136-6BA01-0CA0 SIEMENS`、`F-DI 8X24VDC HF`、`63A`、`OLFLEX 150 QUATTRO`、`12 x 1.00` | — | 型号/厂家/整定值/电缆规格 | BOM 重建、选型核对 |
| **功能文本** | `P4 CONTACTORS FEEDBACK`、`SHUTDOWN ENERGIES`、`HYDRAULIC BLOCK: PRESSURE OK` | — | 信号/功能说明（含其中文标注） | 语义检索（"关机能量"） |

### 6.1 两条经实测验证的强约定

1. **位号前缀 = home 图号**：245/252（97.2%）的位号至少在其前缀图号那一页出现。例外很有解释力——`301A1`/`303A1` 画在模块总页 300 上，`402B1` 画在 407 上，`116K1`/`120K1`/`120T1` 只出现在布置图 801 上。→ 可以拿前缀当"最近似来源图"的先验，命中率极高但不能当唯一依据。
2. **交叉引用是"柜内局部"的**：1,669 条里 1,527 条（91.5%）的目标图号在本柜内存在；142 条（8.5%）指向另一个柜，且这些**都带侧别前缀** `A(...)`/`B(...)`（例如主柜 sheet 101 里同时出现 `A(1100-8)` 与 `B(1100-8)`，分别指向 A 腔与 B 腔的盖板电源页）。→ 解析时先在本柜内找；找不到再看侧别前缀；二者都没有才报"跨柜歧义"。

## 8 提取工艺（实现要点，可直接照做）

### 8.1 工具栈

| 方案 | 文本 | 字符框 | 渲染 | 结论 |
|---|---|---|---|---|
| `pypdf`（纯 Python） | ✅ 与 pdfium 逐字一致 | 只有文本矩阵，需自己算旋转/缩放 | ❌ | 适合"只要文字"的服务端场景 |
| `pypdfium2`（PDFium 绑定） | ✅ | ✅ `get_charbox()` | ✅ | **推荐**：一套库解决文本+坐标+出图 |
| `pdfjs-dist`（Node） | ✅ | ✅ | ✅ | 插件若走 Node/浏览器端，用这个 |

本次实测用 `pypdf` 建索引（无原生依赖、快），用 `pypdfium2` 做坐标与渲染校验。

### 8.2 坐标系归一化 + 落墨自检（关键，且可自动化）

- 文本矩阵要**与 CTM 复合**（这两批页面用 `q … cm … Q` 包裹内容，只看 `tm` 会算错）；
- `/Rotate 90` 的 329 页：`显示坐标 = (charbox.bottom, charbox.left)`，显示框 842×595；
- **不要靠肉眼验证**，用落墨率当闸门：把每个词框投到渲染图上统计墨迹命中率。
  实测：329 页 **100%** 命中；24 页 `/Rotate 180` 的针脚页只有 **31%** → 自动暴露方向异常，需单独分支（页型少、页数固定，可硬编码处理或整页回退到"按页跳转"）。
  这个自检脚本（`qa_ink.py`）建议直接进插件的入库流水线：**每份 PDF 入库都跑一遍，低于阈值就降级为"仅文本索引"**。

### 8.3 词聚类：先按行切，再按间隙切

先用 `get_text_range()` 的换行切成"行"（PDFium 已经做了行分割），再在行内按字间间隙切词。
**反例代价**：直接用几何聚类（按 y 聚类 + 按 x 间隙切）会把 `(220-14)` 拆成 `(`、`220`、`-`、`14`、`)` 五段，交叉引用**一条都抽不到**（实测从 1,669 条掉到 0），线号 `210.VS4` 也会被拆散。

### 8.4 字段模板抽取（表格型页面）

三步：**锚点 → 标签取值 → 按列带宽归属**。
- 锚点：`Cable:`、`TERMINAL :`、`Type:`、`NUMBER/COLOUR` 等固定标签；
- 取值：标签同一行右侧的连续词；
- 归属：同一张纸上可能有 3–6 个并列块（电缆页是 3 列网格，x 间距 260 pt），必须**先按列 x 带宽把词分给块**，再按 y 排序。只按 y 分行会把三个电缆符号的行混成一条（实测：混行时 `strands`/`section` 全部串行，抽出的表 90% 是错的）。
- 近邻行合并：模板里有 `AG`/`1m`/`AG` 这种被画成两行的"同一行"，按"y 差 < 4.5 且 x 区间不重叠"合并。

### 8.5 交叉引用语法与消歧

```
(220-14)        → 本柜 sheet 220 第 14 列
A(1100-8)       → A 腔柜 sheet 1100 第 8 列（优先 A 柜；B 同号则歧义）
110-7           → 裸写形式（端子页常见），需校验"目标图号存在 + 列号 ≤ 39"
13-14 NO        → 不是交叉引用（触点编号），靠"目标图号必须存在"过滤掉
```

消歧顺序：本柜存在同名图号 → 用侧别前缀 → 报歧义。实测 100% 可解析、8.5% 需跨柜。

### 8.6 数据模型（建议）

```
document      { id, path, sha256, pages, producer, printed_at, project{}, blocks[] }
block         { id, name: "AG"|"COF-BASE-A"|…, pdf_pages[from,to], sheets[] }
sheet         { block, no, title, category, loc, rev, date, page, prev, next, col_labels, row_labels }
occurrence    { sheet, page, bbox{x,y,w,h}, text, kind }      // kind: tag|wire|cable|addr|term|text|part
xref          { from_sheet, page, raw, target_sheet, column, side, bbox, resolved_block }
entity        { kind, name, home_sheet(推断), occurrences[] } // 由 occurrence 聚合
table         { kind: cable|terminal|channel|connector|bom, rows[] }  // §7.2 的结构化结果
```

主键：`sheet = (document, block, no)`；交叉引用指向 `block` 内，跨柜时才带 `side`。

## 9 插件形态建议

### 9.1 与现有插件的关系

仓库里已有三块相邻能力：`dsh-engineering-context`（工程事实：TIA 项目、源树、设备）、`dsh-engineering-graph`（设备知识库：块逻辑/SQLite 图谱）、`ui-*`（界面）。这份图纸要插进去，最自然的定位是**"第四个事实源"**：

```
              TIA 项目（.ap17）          电气图纸（PDF，本项目）
                     │                          │
        engineering-context（工程事实总线）  ←→  新插件：drawing-index（图纸事实源）
                     │                          │
              engineering-graph（设备知识库） ────┘
                     │
                  ui-*（界面）
```

- 新插件职责：**索引 + 检索 + 定位**（不做网表、不做 CAD）；
- 对外只暴露两样东西：一个服务（`drawingIndex`）+ 一组工具；
- 与 TIA 的接缝是 **PLC 地址**（`%I400.0` ↔ TIA 变量表）和**位号**（`220KA3` ↔ 硬件配置/IO 通道）：两边都能对上，就能做"从 TIA 变量跳到图纸通道页"的联动，这是最有价值的交叉查询。

### 9.2 工具面（建议的 6 个工具）

| 工具 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `drawing_list_sheets` | `document?`, `block?`, `category?` | 图号/标题/柜/页/模板 | 目录（自建，不用 SUMMARY） |
| `drawing_get_sheet` | `block`, `no` | 图框字段 + 交叉引用列表 + 文本行 + 页图 | 单页详情 |
| `drawing_find` | `query`（位号/线号/地址/文字） | 命中列表（页/柜/框/上下文） | 全文 + 实体检索 |
| `drawing_resolve_xref` | `block`, `raw` | `target_sheet`, `column`, 目标页与列范围 | 跳转语义 |
| `drawing_where_used` | `entity`（如 `W015`、`220KA3`、`X3`） | 全文档出现位置 + 角色（定义/引用/柜内布置） | 反向查询，实测 `220KA3` → 4 页（电源页/通道页/本位/布置图） |
| `drawing_export_table` | `kind: cable\|terminal\|channel\|connector` | 表格（CSV/XLSX/JSON） | 用于重建缺失的电缆清单/BOM |

可选：`drawing_render`（`block`, `no`, `region{column,row}` → PNG）——供界面高亮用，插件外部可以只给"页 + 框"坐标让前端渲染。

### 9.3 界面（"查阅"体验的关键三件事）

1. **图册条**：按柜 → 号段 → 图号分层，缩略图 + 标题，支持 `上一张/下一张`（图框自带）与"跳图号"。
2. **交叉引用可点**：图面上 `(220-14)` 高亮成热区，点击 → 打开目标页并**缩放到第 14 列**（列宽 = 图框 39 等分，位置可从列标反算，无需读图元）。
3. **位号 where-used 侧栏**：选中 `220KA3` → 列出"定义页/引用页/布置图页"，点任一条跳到对应框。

### 9.4 存储与成本

- 每份 PDF 生成一个 sidecar（JSON 或 SQLite），键 = 文件 sha256；本项目实测：文本 74,598 词簇、索引 JSON 约几 MB 量级，**解析一份 353 页图纸约 4 秒**（纯 Python + pdfium），完全可以在工具调用里同步完成。
- 纹理/渲染按需（缩略图懒生成），不要预渲染 353 页。
- 无需 OCR、无需外部服务、无需联网——**离线可跑**，这点对工厂环境很重要。

### 9.5 风险与工作量

| 项 | 评估 |
|---|---|
| 厂商格式绑定 | 强：本解析器吃的是 SEE 的输出约定（位号前缀、交叉引用语法、模板标签）。换 EPLAN/AutoCAD Electrical 要另写一套适配层 → **建议一开始就把"抽取规则"做成与 PDF 无关的策略对象（provider）** |
| 图纸版本漂移 | 目录已与纸面脱节，说明这类项目"图改了但目录没重生成"是常态 → 索引必须每次从页面现场生成，并保留"与上一版对比"能力 |
| 24 页方向异常 | 已知、可绕过（按页跳转 / 硬编码旋转） |
| 表格模板的鲁棒性 | 电缆页已 98%；端子/通道页需要各写一份模板与回归样本 |
| 不做网表的后果 | "这根线到底导通到哪"这类问题仍需人看图；但**"这根线画在哪几张图"能答**，实测量级已足够支撑日常查阅 |

## 11 解析与检索的实现决策：代码还是模型？

这一节回答三个具体问题：**解析要不要交给模型、要不要落盘、按需查询要不要发截图**。结论都基于第 7、8 章的实测。

### 11.1 解析交给代码，模型只消费"检索结果"

| 环节 | 由谁做 | 依据 |
|---|---|---|
| PDF → 词簇/字符框 | **代码**（pdfium） | 353 页 4 秒、0 token、100% 可复现 |
| 词簇 → 图号/位号/线号/交叉引用/表格 | **代码 + 规则** | 规则来自 SEE 的制图约定（§6、§8.4） |
| PDF → 像素（给人看） | 代码（渲染） | 只在人要看图时 |
| "这个词是什么意思""这两张图是什么关系" | **模型** | 只在检索结果上做推理，不碰原图 |

**为什么不让模型直接读图**：

1. 文本层是旋转的，`pypdf` 直出的阅读顺序是乱的——同一行的字段会被打散到不同位置，模型看到的是一锅粥。实测：不按"行"切分时，交叉引用抽取从 1,669 条掉到 **0**，说明"顺序"本身就是解析难度所在。
2. 模型读图不可复现：同一个问题问两次，可能给出不同的端子号。
3. 成本差一个数量级（见 11.3）。

**需要"矢量图纸识别的专用工具"吗？** 需要的是三个**确定性**基础件，而不是"图纸识别 AI"：

| 需要的能力 | 现成方案 | 是否要自研 |
|---|---|---|
| 文本 + 字符框（含旋转/缩放归一） | `pypdfium2` / `pdfjs-dist` | 否，但坐标归一化要自己写（§8.2） |
| 页面渲染 / 区域裁剪 | 同上 | 否 |
| 结构化（位号/线号/交叉引用/表格模板） | 无 | **是**，这是本项目真正的工程量，且跟厂商约定绑定（SEE / EPLAN 各一套 provider） |

**明确不做的"专用工具"**：符号识别、矢量图元→器件/网表重建。第 7.3 节已判定：这套图没有可复用的 symbol XObject（内容流里只有 `m`/`l`/`S`），要恢复连接只能做几何推理，且"查阅"用不到。

### 11.2 必须落盘，但省 token 只是副作用

落盘（每份图纸一个 sidecar 索引）的真正理由，按重要性排序：

| 理由 | 说明 |
|---|---|
| 确定性 / 可复现 | 同一问题两次查询必须同一答案；模型读图做不到 |
| 速度 | 一次解析 4 s；一个会话里会被查几十次 |
| 可 diff | 图纸换版后能自动比对"哪张图改了"——这类项目"图改了但目录没重生成"是常态（§4） |
| 查询能力 | 落盘后才可能"全文档 where-used""交叉引用图谱"，这些是逐页看图做不到的 |
| 省 token | **副作用**，不是主因（见 11.3） |

落盘形态建议（单项目 10 MB 量级，可接受）：

```
drawing/<name>.pdf                   原件（用户给路径时复制进来，不移动、不覆盖）
drawing/_index/<sha256>/index.sqlite  sheets / occurrences / xrefs / entities / tables + FTS5
drawing/_index/<sha256>/profile.json  图纸档案卡（§11.4），几百 token
drawing/_index/<sha256>/render/       按需裁剪图缓存（LRU）
```

键用 `sha256` 而不是文件名：同一份图纸被重新上传、改名、换目录都不会重复解析。

### 11.3 按需查询绝不整页发模型

实测口径（本 PDF，353 页）：

| 投喂方式 | 量级 | 评价 |
|---|---|---|
| 全文 506k 字符 ≈ **158k token** | 一次塞不进，也不该塞 | ✗ |
| 单页文本 1,433 字符 ≈ **450 token** | 便宜，**但顺序是乱的、字段关联丢失** | ✗ 单页也不行 |
| 单页 A4 渲染 1,853×1,309 px | 视模型分块，约 **1–3k token/页**，且不可复现 | ✗ 默认不用 |
| **裁剪区域** 600×400 px | 约 **200–500 token** | ○ 只在"要看形状"时 |
| **检索结果**（命中位置 + 该页结构化字段 + 表格行） | 约 **50–200 token** | ✓ 默认形态 |

一次典型的"这根线去哪了"交互：`drawing_search` → `drawing_sheet`×2 → `drawing_xref`，3 次调用合计约 300–600 token。换成让模型看 3 张图：约 4,800 token，还容易看错。**差约一个数量级。**

所以工具返回的应该是**结构化片段**，例如：

```jsonc
// drawing_search("W015")
{"hits":[{"cabinet":"AG","sheet":210,"page":25,"bbox":[358,242,392,252],"role":"cable",
          "context":"210.06 | X3:14 | W015 0.00m 12x1.00 OLFLEX 150 QUATTRO | (310-33)"},
         {"cabinet":"AG","sheet":3000,"page":58,"bbox":[…],"role":"detail"}]}
```

### 11.4 图纸档案卡：解析一次，之后"知道怎么查"

初次解析除了建库，还要产出一张**极简档案**（`profile.json`，约 300–500 token）。它既是给人看的确认信息，也是模型"日后怎么检索"的说明书：

### 11.5 什么时候才允许发截图（视觉回退）

默认不发图。只有四种情况回退到渲染，且**裁区域不整页**：

| 触发 | 说明 |
|---|---|
| 用户明确要看 | "把这张图发我""这块接线长什么样" |
| 页面在异常清单里 | 24 页方向异常页，文本坐标不可用 |
| 文本置信度低 | 落墨率闸门低于阈值、或模板字段缺失（如 `Ø` 被解成 `の`） |
| 图形类问题 | "柜门开孔怎么排""这个符号是什么"——这类问题文本层本来就没有答案 |

工具设计上把"给模型看"和"给人看"分开：`drawing_render` 返回图片路径，由界面展示；**不要**让渲染结果默认进模型上下文。

### 11.6 对"自动监测 workspace/drawing"的实现建议

DSH 插件拿不到"后台持续监听目录"的钩子，也不该有——目录变化没有天然的会话边界。可行的做法是三条叠加，效果上等于"自动"：

1. **提示词规则**（插件注入一段短说明）："当用户提到图纸/原理图/接线/电气图，先调 `drawing_status`。"
2. **`drawing_status` 只做轻量扫描**：`stat` 一下 `drawing/` 目录与 `_index/`，不解析、不读 PDF，返回"有没有 / 哪几份 / 是否已建索引"。
3. **会话首次需要时才解析**：用户确认后 `drawing_open` 才复制文件、算 hash、跑解析（4 s），并把 `profile.json` 返回给模型。

入库规则（用户两种给图方式）：

| 来源 | 处理 |
|---|---|
| 用户给源路径（如 `E:\…\xxx.pdf`） | **复制**到 `drawing/<name>.pdf`（保留原件不动），再走到 hash/解析 |
| 用户上传附件 | 宿主已落盘（`.dsh/attachments/...`），复制到 `drawing/` 后同样处理 |

版本冲突：同名但 hash 不同 → 存为 `drawing/<name>__<sha8>.pdf`，两份都保留（图纸换版是常态，能对比是特性不是负担）。
