6 · R1：为什么「提交」现在离不开 TIA

这是拆包的第一块砖，必须先在 context 里做（resolveDevice 同时被 sync 和 commit 用）。 左边是今天的真实链路，右边是 R1 之后的链路。

改动前的 project_commit 大半个流程在问 TIA

  1. resolveScope() —— 定位 workspace
  2. engineeringAccess(ctx)，取不到抛 tia_access_unavailable
    commit.ts:85-92
  3. access.readTiaSession() —— 必须有 TIA 控制器
    device.ts:81
  4. 闸门：控制器没跑 / 工程没开
    device.ts:90-103
  5. 闸门：0 个 PLC 报错；>1 个 PLC 直接拒绝
    device.ts:104-117 · multiple_plc_unsupported
  6. 到这里才读索引 devices[] 拿目录
    device.ts:126
  7. git add + commit（context 自己的 runner）
不装 TIA 的组合里，project_commit 永远跑不了——尽管 source 树、evidence、git 都在磁盘上。

R1 之后的 project_commit 磁盘优先，TIA 只做交叉校验

  1. resolveScope() —— 定位 workspace
  2. 读索引 source/_dsh-engineering-context.json 的 devices[]
  3. 没有索引 → 列 source/*/_evidence.json 推断
  4. 0 个 → device_not_found；多个 → 要求显式 device 参数（不再拒绝）
  5. （可选）engineeringAccess 在时比对会话，不一致 只告警
  6. git add + commit 经 gitContext
R1c：project_sync / project_status 保留 TIA 依赖（它们本来就要开工程）—— 只有 commit / diff / history 这条线脱离。
验收：断网 + 不装 TIA + TIA 未开工程，三种情况下都能对一个已有 source 树与 evidence 的仓库做 project_commit 的 plan 与 commit。
