# 工作笔记约定（Notes Convention）v0.1

> 状态：**提案，待拍板** · 2026-10-21 · 适用：所有 DSH workspace
>
> 一句话：模型产生的过程性文档只允许一种落盘形态——workspace 根目录下的 `notes/`。
> 它有固定命名、YAML 头、生命周期和自动索引；正式交付文档仍然只进 `docs/`。

---

## 1. 问题

现状不是「模型写了 markdown」，而是四件事同时缺失：

| 缺失 | 后果 |
|---|---|
| 位置 | `note/`、`notes/`、根目录 `*.md` 各写各的，下个会话找不到 |
| 命名 | `final.md`、`分析.md`、`v2-新.md` 无法排序、无法稳定链接 |
| 元数据 | 不知道哪篇还有效、哪篇已被推翻、依据是什么 |
| 生命周期 | 临时草稿与已采纳结论混在一起，越积越多 |

再叠加 D23/D26 的两层 agent：leader 会把「已读事实」写成 notes 交给 expert。
没有约定时，这个交接工件本身也是随机的。

---

## 2. 目标与非目标

**目标**

- 一个位置、一套命名、一个模板、一份索引。
- 每篇笔记都能回答：结论是什么、依据在哪、现在是否有效、被谁替代。
- 机器可校验（脚本 lint），后续可被工具/插件接管。
- 对现有 `docs/` 零侵入：笔记是过程资产，不是交付文档。

**非目标（v1 不做）**

- 不做数据库、不做全文检索服务、不做 Web UI。
- 不做自动归档、不做 session 自动关联。
- 不改 `docs/` 的组织方式，不改各包自己的 `docs/`。

---

## 3. 方案

### 3.1 三层分离

| 层 | 位置 | 落盘 | 入库 | 典型内容 |
|---|---|---|---|---|
| 会话推理 | 对话本身 | 否 | — | 试错、临时推演、一次性问答 |
| 工作笔记 | `<workspace>/notes/` | 是 | 是 | 调查结论、方案取舍、交接事实、验证报告 |
| 正式文档 | `docs/` 或包内 `docs/` | 是 | 是 | 面向使用者的说明、决策记录、路线图 |

规则：**能留在对话里的，不要落盘；落盘的，只进 `notes/`；要给人长期读的，才提升到 `docs/`。**

为什么不是别的：

- 不是 `note/`：单数、无结构，和 `notes/` 并存必然分裂；本约定生效后禁止新建。
- 不是 `docs/notes/`：`docs/` 是交付物，会被发布、评审；笔记的生命周期和读者都不同。
- 不是 `~/.dsh/notes/`：笔记要跟代码同仓，才能相对链接、review、`git log` 追溯；跨 workspace 检索是 v2 的事。
- 不是数据库：v1 用文件 + git，零依赖；检索需求明确后再加 FTS，文件仍是真相源。

### 3.2 目录

```
<workspace>/
└── notes/
    ├── README.md              # 10 行入口：这是什么、怎么写、看 INDEX
    ├── INDEX.md               # 生成物，禁止手改
    ├── _templates/
    │   └── note.md            # 唯一模板
    ├── _archive/              # status: archived 的笔记
    ├── assets/<slug>/         # 可选：该笔记的图片/图表
    └── <slug>.md              # 其余全部平铺
```

- **平铺，不建主题子目录**：一个 workspace 一个工程作用域（D5），平铺足够；超过约 200 篇再议分区，届时只按 `kind` 或 `project` 分，不按人分。
- `assets/` 只放图片/图表，单文件 ≤ 1 MB；日志、导出物、二进制不进 `notes/`。
- 模板只有一份；`kind` 的差异靠正文小节，不靠多套模板。

### 3.3 命名

- 文件名 = `<slug>.md`，**全小写 ASCII**，`[a-z0-9-]`，2–6 个词，≤ 60 字符。
- 不加日期、不加版本号、不写 `final` / `new` / `v2` / `latest`。版本由 git 和 `supersedes` 表达。
- 中文标题写在 `title`，不写进文件名（跨平台、链接、脚本都更稳）。
- 保留名：`README.md`、`INDEX.md`、`_templates/`、`_archive/`、`assets/`。
- 例：`dtr-rear-voc-door-decoupling.md`、`dtr-after-voc-door-spec.md`、`notes-index-design.md`。

### 3.4 Front matter（必填 7 项）

```yaml
---
title: DTR 与后 VOC 门解耦：事实与方案
summary: 后 VOC 门由 DTR 请求才打开，把 FullOpen 直接 AND 进 N50 会成环；应改由疏散意图预开门。
kind: investigation
status: active
created: 2026-10-20
updated: 2026-10-21
tags: [tia, dtr, voc-door]
project: PEI_SinoARP_SWT2
related:
  - packages/dsh-engineering-graph/docs/...
---
```

| 字段 | 必填 | 取值 | 说明 |
|---|---|---|---|
| `title` | 是 | 字符串 | 与正文 H1 完全一致 |
| `summary` | 是 | ≤ 80 字 | 一句话结论；INDEX 和检索用它 |
| `kind` | 是 | `investigation` / `design` / `spec` / `report` | 调查 / 方案 / 实施规格 / 执行报告 |
| `status` | 是 | `draft` / `active` / `decided` / `archived` | 见 3.6 |
| `created` | 是 | `YYYY-MM-DD` | 首次创建 |
| `updated` | 是 | `YYYY-MM-DD` | 任何实质修改都要更新 |
| `tags` | 是 | 小写 kebab ASCII 列表 | 至少 1 个；跨笔记检索的主键 |
| `project` | 否 | 字符串 | 工程名，和 TIA/workspace 对应 |
| `related` | 否 | workspace 相对路径列表 | 代码、文档、其他笔记 |
| `supersedes` | 否 | slug 或路径列表 | 本篇替代了谁 |
| `superseded_by` | 否 | slug 或路径 | 本篇被谁替代（归档时必填） |

约定：

- 不用中文 key，不用嵌套对象，不用多行 YAML（保证零依赖可解析）。
- `related` 用 **workspace 相对路径**（如 `packages/x/src/y.ts`），不用 `../`；正文里的链接仍用标准相对 Markdown。

### 3.5 正文模板

```md
# <与 title 相同>

## 结论

<先给答案。≤ 10 行。读者只读这一段也能做决定。>

## 背景

<为什么会有这篇；问题边界；不解决会怎样。>

## 依据

<每条事实给来源：`path:line`、命令、工具调用、commit。
 推断单独标 **[推断]**；未验证标 **[待验证]**。
 不要写「据说」「应该是」。>

## 方案与取舍

<可选。考虑过的选项、为什么选这个、代价是什么。>

## 风险与未决

<可选。边界条件、失败模式、需要谁拍板。>

## 参考

<可选。外部链接、相关笔记、决策编号。>
```

硬性要求只有两条：`## 结论` 非空；`## 依据` 里的每个关键事实可追溯。其余小节按 `kind` 取舍。

### 3.6 生命周期

```
draft ──► active ──► decided ──► archived
  │          │           │
  └──────────┴───────────┴──────► archived（放弃/过期）
```

| 状态 | 含义 | 允许的修改 |
|---|---|---|
| `draft` | 还在写，结论可能变 | 自由修改 |
| `active` | 当前有效的工作结论 | 可修订，必须更新 `updated` |
| `decided` | 已被采纳（代码/文档/决策已落地） | 只允许勘误、补链接；实质变更开新篇 |
| `archived` | 不再有效 | 只读；移到 `_archive/`，填 `superseded_by`（若有替代） |

规则：

- `active` 的前提是 `## 结论` 和 `## 依据` 都非空。
- `decided` 必须在 `## 依据` 或末尾写明**落地位置**（commit / PR / 文档路径）。
- 被替代时：新笔记 `supersedes: [old-slug]`，旧笔记 `status: archived` + `superseded_by: new-slug`，两边互链。
- 归档不删除。`git` 已经有历史，但索引里保留可发现性。

### 3.7 索引

`notes/INDEX.md` 由脚本生成，禁止手改。内容：

| 标题 | kind | status | updated | tags | summary |
|---|---|---|---|---|---|
| [DTR 与后 VOC 门解耦](dtr-rear-voc-door-decoupling.md) | investigation | active | 2026-10-21 | tia, dtr | … |

- 排序：`active` → `draft` → `decided` → `archived`；组内按 `updated` 倒序。
- 头部写 `<!-- GENERATED by scripts/notes.mjs; do not edit -->`。
- `README.md` 只写「怎么用」，不重复索引内容。

### 3.8 写入规则（模型行为）

1. **默认不落盘**。一次会话能解决的，不写文件。
2. **唯一位置**：`<workspace>/notes/`。禁止 `note/`、`notes.md`、根目录 `*.md`、包内 `notes/`。
3. **值得写的四种情况**（满足其一）：跨会话/跨 agent 要复用；结论依赖多处证据、需要审计链；做了取舍、要记 why；要作为 leader→expert 的交接工件（D26）。
4. **一篇一题**。超过约 300 行或出现第二个独立决策，拆篇并互链。
5. **先查重**：写之前看 `INDEX.md` 和 `tags`；同一主题优先续写现有 `draft/active` 笔记，不新建「v2」。
6. **结论先行，事实与推断分开**。没有出处的断言不写；不确定就标 `[待验证]`。
7. **只有主 agent 写**。子 agent 只读笔记，结论回传主 agent 合并；这样避免并发写（D18）和职责漂移。
8. **改状态要成套**：改 `status`/`updated` → 重新生成 INDEX → 必要时改互链。
9. **敏感信息**：不写 token、密码、客户个人信息；必要处用 `<redacted>`。
10. **不写「过程流水账」**：不逐条记录试错；只留可复用的结论和证据。

### 3.9 Git 与并发

- 默认 **入库**：`notes/**/*.md` 全部跟踪，包括 `_archive/`、模板、INDEX。理由：结论要可 review、可追溯、可回滚。
- 提交信息：`docs(notes): <slug> — <一句话>`；纯调查笔记单独提交，不和代码改动混。
- 与代码改动强相关的笔记，可以在代码提交信息里引用 `notes/<slug>.md`，但不要把两者塞进同一个 `git add -A`。
- 并发遵循 D18：按 hunk 拆提交；拆不开就在提交信息里写明归属。禁止 `git add -A`。
- 如果某个 workspace 的笔记确定不宜入库：整目录加 `.gitignore`，但要在 `notes/README.md` 里写明；这是例外，不是默认。
- 不是 git 仓库的 workspace 同样适用目录与元数据规则，只是没有「入库」这一步。

### 3.10 迁移

一次性动作，按 workspace 做：

1. 盘点：`note/`、`notes/`、根目录散落的分析型 `*.md`。
2. 移到 `notes/<slug>.md`，按 3.3 改名。已跟踪的文件用 `git mv` 保留历史；workspace 不是 git 仓库（试点 `Create Project Test2` 就是）时用 `Move-Item`。
3. 补 front matter；`kind`/`status` 按内容判定：仍在用的给 `active`，已落地的给 `decided`，过期的给 `archived`。
4. 改正文里指向旧路径的链接；补 `related`。
5. 生成 INDEX；删除空的旧目录。
6. 在提交信息里附旧→新路径映射（或写进 `_archive/` 的一篇迁移说明，二选一，不双写）。

试点：`C:\Users\Ansel\Documents\deepseek-harness\Create Project Test2\notes\` 现有两篇：

- `rear-voc-door-dtr-decoupling.md` → `notes/dtr-rear-voc-door-decoupling.md`（`kind: investigation`）
- `dtr-after-voc-door-modification-spec.md` → `notes/dtr-after-voc-door-spec.md`（`kind: spec`）

本仓 `dsh-automation-suite` 当前没有 `note/`/`notes/`，迁移为空，可直接建 `notes/README.md` + 模板作为范式。

## 4. 验收

v1 的「完成」标准：

1. `notes/README.md`、`notes/_templates/note.md`、`notes/INDEX.md` 存在，INDEX 可重建。
2. `node scripts/notes.mjs check` 退出码 0，覆盖：
   - 文件名合法、无保留名冲突；
   - front matter 必填项齐全、枚举合法、日期合法、`updated >= created`；
   - H1 与 `title` 一致；`## 结论` 非空；
   - `archived` 必在 `_archive/`，其余不在；
   - `superseded_by` 指向存在的笔记且目标为 `archived`；互链成对；
   - 正文相对链接可解析；
   - INDEX 与磁盘一致（`--check` 不写盘）。
3. 试点 workspace 跑通：两篇旧笔记迁移后 lint 通过；expert 按 brief 读笔记，不再重读同一网络（对照 D26 的度量）。
4. 两周内没有新增 `note/`、根目录 `*.md`、包内 `notes/`。

## 5. 后续规划（v1 之外）

| 能力 | v1 | 后续 |
|---|---|---|
| 写入 | AGENTS.md / persona 规则 | DSH 工具 `note_write`，schema 校验、自动填元数据 |
| 检索 | INDEX + `grep` | SQLite FTS / `notes_search`，按 tag、project、status 过滤 |
| 关联 | 相对链接 | 关联知识图谱对象（device/block/network id）、session id |
| 生命周期 | 手工改 `status` | stale 检测、到期提醒、自动归档建议 |
| 提升 | 手工复制到 `docs/` | `notes promote <slug>`：改路径、改链接、归档原笔记 |
| 展示 | 文件 | Web 面板：按状态/标签浏览、diff、跳转代码 |
| 并发 | 主 agent 单写者 | 多写者时的锁/分支策略（若真需要） |
| 度量 | 无 | 笔记复用率、expert 重读率、笔记→决策转化率 |
| 全局 | 每 workspace 一份 | 跨 workspace 的只读聚合索引（不合并文件） |

**对后续的约束**（避免 v1 被推翻）：

- 文件是真相源，INDEX/DB 都是派生，必须可重建。
- front matter 只增字段、不改语义；改语义要迁移脚本。
- 笔记不复制 `docs/` 的内容；提升是「移动 + 归档」，不是「再写一份」。
- 任何自动化都不能绕过 `status`：`decided` 不被静默改写。
