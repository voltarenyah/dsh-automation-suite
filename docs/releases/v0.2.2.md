# dsh-automation-suite 0.2.2 — DSH desktop title bar

This is a shell-only visual/UX release. It changes no profile or plugin content
and no installer flow; it makes the desktop shell's window match the official
DeepSeek Harness desktop app and removes the line that appeared above the title
bar.

## Added

- **Frameless window matching the DSH desktop app**: the DSH web client already
  reserves a 40 px Windows title strip when the desktop marker is present. The
  shell now sets that marker and renders the `Application` / `Edit` caption menus
  and the minimize / maximize / close controls inside it, using the DSH theme
  tokens (light/dark follow the app theme).
- Dragging the strip, double-click maximize/restore and the system menu on it are
  handled by WebView2's non-client region support (`IsNonClientRegionSupportEnabled`),
  the same interaction model as the official Electron app.
- `Application` → About / Open Logs / Run Doctor / Exit; `Edit` → Undo, Redo, Cut,
  Copy, Paste, Select All. Paste reads the host clipboard over WebMessage and
  inserts with `execCommand("insertText")`, preserving the undo stack.
- The old 30 px status line and `Ready` text are gone; startup uses a full-client
  loading layer that hides after navigation.
- The initial window uses 90% of the monitor work area and centers itself (the
  old fixed 1440×900 physical size was only ~740 CSS px wide at high DPI and made
  the DSH layout collapse the sidebar).

## Fixed

- **Thin black line above the title bar (light and dark theme)**: the window's
  client area now covers the whole window via `WM_NCCALCSIZE`, so the title strip
  starts at the visible top edge instead of below the system 8 px sizing frame.
  `DWMWA_BORDER_COLOR = DWMWA_COLOR_NONE` suppresses the DWM 1 px border.
  Theme detection now uses the application's own `data-ds-dark-theme` marker, not
  the OS `prefers-color-scheme` (which used to paint the frame black in light
  mode on a dark Windows theme).
- Because there is no native non-client frame, resizing is initiated from the web
  content: left/right/bottom edges detect a press and ask the host to start the
  regular Win32 sizing loop (`WM_NCLBUTTONDOWN`). The 40 px top strip remains the
  drag region; maximized clients are pinned to the monitor work area.

## Verification

- `pnpm -r test` (with `DOTNET_ROOT` pointed at `.dotnet10`), `pnpm -r build`,
  `pnpm -r typecheck`.
- 0.2.2 silent install + fixed profile + shell `--smoke-test`.
- Manual: strip drag, double-click maximize/restore, edge resize, window buttons,
  both menus, copy/paste with the system clipboard, close-to-tray, Exit (DSH child
  process gone), light and dark themes.

## Known limitations

- The window buttons are drawn by the web page, so the Windows 11 snap-layout
  flyout (hovering the maximize button) is not available. Dragging to a snap zone
  and double-clicking the strip still work.
- The top 40 px strip is the drag region; resize from the left, right or bottom
  edges.

## Upgrade

Exit the running app, then run this setup with the same `DSH_HOME` used by the
previous version (or let it use the default). The installer updates the shell and
app layer and keeps the fixed profile; previous `cordis.patch.yml` overrides are
backed up and merged.
