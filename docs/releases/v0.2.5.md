# dsh-automation-suite 0.2.5 — plugin installation, simulation snapshots, safer sync

This release fixes the desktop app's Plugins page and updates the PLCSIM and TIA
plugins. The installer flow is unchanged (per-user setup), but the shipped
profile now keeps its vendored tarballs and a `pnpm-lock.yaml`, so pnpm can
install into it on a machine that did not build it.

## Fixed

- **The Plugins page could not install any plugin** (since the app layer
  existed, 0.2.0–0.2.5). Two independent blockers:
  1. `build-app-layer.mjs` materialized the profile in a staging directory and
     copied it out with its pnpm metadata intact, so
     `node_modules/.modules.yaml` recorded the build machine's `storeDir` and
     `virtualStoreDir`. pnpm compares both before resolving anything, so the
     first `dsh plugin add` died with `ERR_PNPM_UNEXPECTED_VIRTUAL_STORE` (or
     `ERR_PNPM_UNEXPECTED_STORE` when the user name differs).
  2. The build then deleted `tarballs/` and `pnpm-lock.yaml` and rewrote the
     suite's 15 private plugins to bare versions. They are on no registry, so
     even a normalized profile failed with `ERR_PNPM_FETCH_404`: `pnpm add`
     re-resolves every direct dependency of the importer.

  The app layer now keeps `tarballs/`, `pnpm-lock.yaml` and the `file:` specs.
  After copying the profile, the installer runs
  `scripts/normalize-profile-pnpm.mjs`, which asks pnpm for the store this
  machine actually uses and rewrites `.modules.yaml` and the workspace state
  (verified before writing, rolled back on failure). `doctor` gained a
  plugin-install check that fails — not warns — when the metadata does not
  match this machine. `scripts/test-plugin-add.mjs` is the regression test: it
  builds a synthetic layer under a "build user", copies it to a different
  user/home/store, proves pnpm still rejects the un-normalized copy, normalizes,
  then runs the real `dsh plugin add` twice and checks the profile still loads.

- **A safety-only change could not be versioned.** The PLC checksum covers only
  the compiled standard program, so an edit confined to the safety program left
  it untouched; `project_sync`'s checksum fast path answered `unchanged` and
  `project_commit` refused with "Nothing to commit". `project_sync` now accepts
  `force`, forwarded to the controller as `force_scan` to skip the fast path.
  A skipped scan is reported as such, and `project_status` shows
  `checksum-matches` plus an explicit "Safety program: NOT compared" line
  instead of the misleading `in-sync`.

- **An export that skipped every existing file wiped the manifest.** Skipped
  objects now keep their rows in `_manifest.json`, verified from disk.
  `overwrite=true` exports to a sibling temporary file and `File.Replace()`s it,
  so an Openness refusal leaves the previous file intact instead of replacing it
  with a failure record.

- **New Session failed with `agent-preset/invalid` on DSH 0.2.2.** The
  `preset-leader` row for `dsh-tool-subagent-control/list-agents` no longer
  exists in 0.2.2; it made the whole preset invalid. The row is removed and
  `tool-subagent` uses the 0.2.2 `modelSelection` + `modelDiscovery` keys.

## Changed

- **PLCSIM Advanced snapshots are workspace-scoped.** Snapshots were saved under
  the host process cwd, so `<workspace>/.dsh/simulation/` stayed empty and a
  host restart or another workspace could not find them. The root now comes
  from the session workspace and travels to the controller as `snapshot_root`;
  an explicit `snapshotRoot` config still pins a shared folder.
  `simulation_instance(action="snapshots")` and `simulation_status` list the
  workspace snapshots plus the instances the Runtime Manager still holds.
  `create` refuses with `snapshots_available` while a snapshot exists unless
  `confirm_new=true`, so the user chooses "resume the old snapshot or create a
  new instance". Tool descriptions state the certificate rule up front: a new
  virtual device has a new MAC and a new self-signed certificate, so its first
  Connect needs one manual click in the TIA Portal UI, while resume/restore of
  a snapshot keeps the original identity and needs neither a click nor a
  download. Results always render a `Key facts:` line
  (name/state/cpuType/ip/snapshots).

- **F-CPU simulation types.** `cpu_type` gained the `1511F`–`1518F` families and
  `cpu_model` maps an order number or type name (A = standard, F = fail-safe);
  `unspecified` remains available. PLCSIM Advanced V7 cannot load F project data
  into a standard-CPU instance (manual §7.4), and V17 Openness refuses an
  F-activated PLC with `download_unavailable`, so that download has to happen in
  the TIA Portal UI.

- **Documentation and site.** `docs/tia-version-members.md` (D36) freezes how
  the interface-plugin family carries V17 and V18: one package per version, one
  active member at a time switched by the Plugins-page bundle toggle, followed
  by a client restart. The site now uses the desktop shell's brandmark for the
  favicon/header, points at the Releases page above the installer walkthrough,
  and links the Git CLI row to the official Git for Windows download page.

## Upgrade

Exit the running app, then run this setup with the same `DSH_HOME` used by the
previous version (or let it use the default). The installer updates the shell and
app layer, keeps the fixed profile, backs up the previous `cordis.patch.yml` and
merges user overrides. Because 0.2.0–0.2.5 shipped a broken profile for plugin
installs, re-running this setup is also the fix for an existing 0.2.5 test
install.
