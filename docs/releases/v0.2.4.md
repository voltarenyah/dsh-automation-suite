# dsh-automation-suite 0.2.4 — issue reporting and taskbar fix

This release updates the desktop shell only. The plugins and profile are the
same as 0.2.3, and the installer flow is unchanged.

## Added

- **`Application → Report Issues…` (报告问题…)**: the title-bar menu and the
  tray menu can now open
  <https://github.com/voltarenyah/dsh-automation-suite/issues> in the default
  browser, so users can report bugs without leaving the app. The click is
  written to the shell log (`opening the issue tracker: <url>`); when no
  browser can be started, a message box shows the address for copying.

## Fixed

- **Taskbar became unclickable after maximizing the shell**: the borderless
  shell is a `WS_POPUP` window, so Win32 maximized it to the whole monitor and
  the window covered the taskbar (its fullscreen heuristic then demoted the
  taskbar from topmost). The shell now handles `WM_GETMINMAXINFO` and pins the
  maximized rectangle to the monitor work area, including secondary monitors.
  After maximizing, the taskbar icons, clock/Quick Settings and Start all
  respond again.

## Documentation

- The project site is now bilingual (EN/中文): the home page and the
  "Get started" page, including a walkthrough with the six installer screens,
  the running-session shot and the TIA Openness access note. The site is
  published on GitHub Pages and is not part of the installer.

## Verification

- `pnpm -r build` and `pnpm -r typecheck` exit 0. Every workspace test suite
  that this release touches passes (graph engine 128, TIA Openness 111/1 skip,
  the remaining packages green). The vendored `dsh-tool-git` dev suite does not
  run on host `dsh-tools` 0.2.2-rc.1, which moved the tool executor out of
  `ToolRuntime` and requires a separate executor plugin the package's test
  harness does not mount; the plugin itself is byte-identical to 0.2.3.
- `build-app-layer.mjs --version 0.2.4`: offline `--dump-config` + doctor.
- Shell `--smoke-test` after rebuilding the self-contained shell.
- 0.2.4 silent install + fixed profile + doctor + shell smoke.

## Upgrade

Exit the running app, then run this setup with the same `DSH_HOME` used by the
previous version (or let it use the default). The installer updates the shell
and app layer and keeps the fixed profile; previous `cordis.patch.yml`
overrides are backed up and merged.
