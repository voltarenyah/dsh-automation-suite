# dsh-automation-suite 0.2.6 — release gates, handoff provenance, local-only source index

This release adds no new user-facing features. It clears the test gate that had
been red on every DSH 0.2.2 host, makes a handoff's provenance survive in git
history, and stops committing the machine-local source index. Plugin runtime
behaviour is unchanged apart from the handoff import's next-step guidance and a
new `.gitignore` rule in fresh workspaces.

## Fixed

- **`dsh-tool-git`'s 35 failing tests on DSH 0.2.2** (developer gate, not a
  user-facing fault). DSH 0.2.2 changed `ctx.tools.execute()` from a single call
  to a batch dispatched through an executor that must be loaded in the calling
  scope. The test fixture still used the 0.2.1 call shape and never mounted
  `@deepseek-ai/dsh-tool-executor-native`, so every tool call failed with
  `ToolExecutorUnavailableError`. The fixture now mounts the native executor and
  calls the batch API; `src/dsh-runtime.d.ts` mirrors the real 0.2.2-rc.3
  signatures. **No production plugin code changed.**
- **Parallel package tests deleted each other's runtime cache.**
  `dsh-tool-git` and `dsh-tia-openness-v17-min` both extract
  `<DSH_HOME>/plugin-runtime` from the installed `app.asar`, but with different
  root sets (the former needs `dsh-tool-executor-native`, the latter
  `dsh-skill`). Whichever found the cache "incomplete" deleted the whole tree,
  so a concurrent `pnpm -r test` hit `ENOTEMPTY` and lost packages the other
  package had just extracted. A same-version top-up is now **additive**: it
  keeps the existing tree, extracts only what is missing and records the union of
  package names. Only a harness-version change replaces the tree wholesale.

## Changed

- **`source/_dsh-engineering-context.json` is no longer versioned.** It is a
  local hint — it records absolute machine paths (`savedAs`, the retrieved
  archive under the DSH home, device directories) and `handoff_import` rewrites
  it on every import. Committing it put this machine's paths into history and
  left every import as an uncommitted change. Fresh workspaces get the rule
  `source/_dsh-engineering-context.json` from `create_engineering_project`.
  **Existing workspaces must run `git rm --cached source/_dsh-engineering-context.json`
  once** — an ignore rule does not untrack an already tracked file. Readers keep
  treating it as a hint and fall back to `source/<device>/_evidence.json`.
- **A handoff commit now carries its provenance.** `handoff_import`'s next-step
  guidance requires `project_commit(reference: "handoff:<id>")`, and the
  `leader` / `auditor` presets state the same rule. `handoff/` and its
  `handoff.json` stay git-ignored (deliverables plus local state), so the
  `Reference: handoff:<id>` trailer is the only durable link between the commit
  and the package.
- `packages/dsh-engineering-context/docs/PATH-RULES.md` §6 documents the index
  rule alongside the existing git boundaries.

## Known limitations

- **Rebuilding the knowledge graph needs the .NET 10 runtime and `DOTNET_ROOT`.**
  Set `DOTNET_ROOT=%USERPROFILE%\.dotnet10` (or install the .NET 10 runtime
  machine-wide) before `knowledge_ingest`. Without it the engine cannot start and
  the graph stays stale; versioning continues to work.
- **A handoff's commit provenance is a policy, not a hard gate.** `project_commit`
  accepts `reference`; the import result and presets require it. A caller that
  ignores both gets a commit without the `Reference:` trailer.
- **Existing workspaces keep the index tracked until untracked once.** See the
  `git rm --cached` step above.
- F-CPU download/simulation still has to be completed in the TIA Portal UI
  (V17 Openness refuses an F-activated PLC); unchanged from 0.2.5.
- The installer is unsigned; SmartScreen may show “Unknown publisher”.

## Upgrade

Exit the running app, then run this setup with the same `DSH_HOME` used by the
previous version (or let it use the default). The installer updates the shell and
app layer, keeps the fixed profile, backs up the previous `cordis.patch.yml` and
merges user overrides. No profile migration is required beyond the one-time
`git rm --cached source/_dsh-engineering-context.json` in each existing
engineering workspace.
