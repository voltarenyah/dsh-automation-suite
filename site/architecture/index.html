Architecture

A small surface, strictly enforced

The model never gets arbitrary execution. Writes go through a whitelist, a transaction and a read-back check; tools return structured data instead of free-form shell output.

01

Principles

Four rules that decide what a tool may do.

01

Whitelisted operations

The model expresses paths, block names and enums; the controller runs one of its registered operations.

02

Transactional writes

All objects commit or none do — a failed import rolls back.

03

Read-back verification

After an import the project is re-read and each block compared by name, number and language.

04

Structured results

Every tool returns ok / summary / data / error as data, not as prose to parse.

02

Components

Eight packages plus one profile blueprint; each installs on its own.

The blueprint assembles them into one profile and splits the tools across three presets: leader (44), auditor (18), expert (16).

03

How it runs

One process boundary, because Openness demands it.

Openness can only be called from a 64-bit .NET Framework process, so the TIA plugin owns a C# controller subprocess and speaks one JSON object per line over stdio. Requests are serialized; a timeout terminates and restarts the controller.
